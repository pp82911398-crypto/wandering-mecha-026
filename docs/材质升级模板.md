# 材质升级模板（给做场景的模型照着用）

机甲本体已按这个方法升级完（成品间 `finallab/`，代码在 `finallab/surface.js` + `finallab/wear.js`）。
实测结果：每帧耗时**测不出变化**（全身 6.0 → 5.9 ms，近景 3.1 → 3.0 ms，仍稳定 60 fps），画面平均亮度变化 < 1%，没有新增灯、网格、材质或后期通道。
面板"涂装·灯光·做旧"里的"材质升级"勾选框（或 URL `?surf=0`）可以随时关掉对比。

把这套方法搬到场景（机库、港区、码头、混凝土、钢结构）时，按下面的步骤做。

---

## 0. 先搞清楚"为什么看着像塑料"

这次机甲上的原因，场景里通常也一样：
1. **反射里没东西**：环境图只有灰天空，金属和边缘没有亮条可反 → 看着像塑料。**这是最大的问题，也最便宜。**
2. **一整块一个粗糙度**：整面光泽完全均匀，真实材料从来不是这样。
3. **没有微观表面**：没有颗粒、拉丝、划痕，近看是一块平板。
4. **边缘和平面一个样**：真实物体的凸边会被磕碰、磨亮、掉漆。

先确认是哪几条，再动手。

---

## 1. 预算规则（必须遵守）

| 可以用 | 不能用 |
|---|---|
| 一次性烘焙的反射环境图（PMREM） | 新增实时灯（每盏聚光灯约 1.2 ms/帧，见 CLAUDE.md） |
| 一张全场共用的小细节图（512²，启动时程序生成） | `MeshPhysicalMaterial` 的透射、透明涂层、光泽层 |
| 往现有材质的 `onBeforeCompile` 里加几行 GLSL | 新增后期通道（SSR、SSAO 等） |
| 按距离淡出细节 | 每帧重新生成贴图或环境图 |
| | 给每个物体单独建材质（材质数和着色器程序数都会暴涨） |

**改前、改后都要测**（方法见第 7 节）。目标：每帧增加 ≤ 1 ms，平均亮度变化 ≤ 3%。

---

## 2. 第一步：反射环境（收益最大，每帧零开销）

`surface.js` 里的 `studioEnv(renderer, skyMat)`：建一个只用来烘焙的小场景，放原来的天空球，再加几块发光板，用 `PMREMGenerator.fromScene` 烘一次，赋给 `scene.environment`。

```js
const env = new THREE.Scene();
env.add(new THREE.Mesh(new THREE.SphereGeometry(50, 32, 16), skyMat));   // 原天空
const box = (color, k, pos, size) => {                                     // k > 1 = 比天空亮的灯板
  const m = new THREE.Mesh(new THREE.PlaneGeometry(...size),
    new THREE.MeshBasicMaterial({ color: new THREE.Color(color).multiplyScalar(k), side: THREE.DoubleSide }));
  m.position.set(...pos); m.lookAt(0, 0, 0); env.add(m);
};
box(0xf2f5f8, 2.0, [0, 40, 6], [34, 9]);     // 顶部柔光箱
box(0xfff3e6, 2.2, [30, 4, 24], [4, 34]);    // 主光侧的竖长条 → 圆角边、柱子上一道竖向高光
box(0xa9c6e0, 2.0, [-22, 6, -34], [3, 30]);  // 背后冷色轮廓条
// ……地面放一块暗色圆盘，给向下的面一点"地面反光"
const tex = new THREE.PMREMGenerator(renderer).fromScene(env, 0.025).texture;
```

要点：
- **长条比方块好**：长条在圆角边、圆柱上扫出连续的高光线，最显质感。
- 亮度用 `multiplyScalar(k)` 调（PMREM 是浮点图，k > 1 也有效）。
- **场景版**：机库里就按实际顶灯排布放灯条（一排排长条），外景放天空、太阳方向一块亮斑、海面一条暗带、地平线一条亮带。环境图要"像"这个地方，反射才可信。
- 换环境后整体会变亮，用一个系数乘 `scene.environmentIntensity` 把平均亮度拉回原值（机甲用的是 0.8，要实测）。
- 旧环境图留着，开关时切换（`scene.environment = on ? NEW : OLD`）。

## 3. 第二步：一张全场共用的细节图

`detailTexture()`：启动时在 JS 里生成 512×512 的 RGBA 图，四个通道各放一种细节，**必须可平铺**（噪声的格点按周期取模）。

| 通道 | 内容 | 用途 |
|---|---|---|
| R | 细颗粒（3 层周期噪声） | 漆面橘皮、混凝土砂粒的凹凸 |
| G | 拉丝（每行一个随机值 + 轻微弯曲） | 金属拉丝的凹凸和粗糙度 |
| B | 低频斑驳 | 粗糙度大块起伏（避免一整面一样亮） |
| A | 细划痕（随机短线，两个主方向） | 划痕处更粗糙、漆面更浅 |

- `DataTexture` + `RepeatWrapping` + mipmap + `anisotropy 4`，颜色空间 `NoColorSpace`（这是数据，不是颜色）。
- 一张图给全场所有材质用，不同材质只是用不同权重混合这四个通道。
- **场景版**：混凝土多用 R 和 B（加大权重），钢结构用 G，地面加 A。如果要污渍、积水，可以再做第二张图，但同样全场共用一张。

---

## 4. 第三步：三平面投射（模型没有 UV 也能用）

这个项目的程序生成网格大多没有 UV。按**物体自身坐标**从三个方向投射，按法线混合：

```glsl
vec4 triDetail(vec3 p, vec3 n){                       // p = 物体局部坐标, n = 物体局部法线
  vec3 w = pow(abs(n), vec3(4.0)); w /= (w.x + w.y + w.z + 1e-5);
  return texture2D(uDetail, p.yz * uTile) * w.x
       + texture2D(uDetail, p.zx * uTile) * w.y
       + texture2D(uDetail, p.xy * uTile) * w.z;
}
```

- 顶点着色器里传 `position` 和 `objectNormal` 出来（用局部坐标，物体移动、转动时纹理跟着走，不会"游"）。
- `uTile`：机甲用 1/0.8（一张图铺 0.8 单位 ≈ 1.6 m）。**场景尺度不同**（港区 1 单位 = 1 m），要按实际尺寸重新定。
- **静止的大场景物体**（地面、墙）可以直接用世界坐标，还能跨物体连续。

## 5. 第四步：注入到现有材质（一处注入，不新增材质）

本项目所有做旧都在 `wear.js` 的 `patch(mat, k)` 里通过 `onBeforeCompile` 改着色器。材质升级就**加在同一个 patch 里**，用 `k.kind` 选材质类别：

```js
// surface.js
export const KINDS = {
  paint:  { grain: 1.0,  brush: 0.0,  rv: 0.55, scratch: 1.0, edge: 1.0 },
  primer: { grain: 1.8,  brush: 0.0,  rv: 0.8,  scratch: 0.4, edge: 0.4 },
  metal:  { grain: 0.25, brush: 1.0,  rv: 0.6,  scratch: 0.7, edge: 0.8 },
  chrome: { grain: 0.0,  brush: 0.35, rv: 0.25, scratch: 0.3, edge: 0.0 },
  rubber: { grain: 0.9,  brush: 0.0,  rv: 0.35, scratch: 0.0, edge: 0.0 },
};
// wear.js
patch(PAL.frame,  { chip: 0.35, scuff: 0.6, recess: 0.15, kind: 'metal' });
patch(PAL.chrome, { chip: 0, scuff: 0, recess: 0.1, grime: 0.5, kind: 'chrome' });
```

注入位置（MeshStandardMaterial 的着色器片段）：

| 片段 | 做什么 |
|---|---|
| `#include <common>` 后 | 声明 uniform、varying、`triDetail()` |
| `#include <color_fragment>` 后 | 采样细节图 → `sD`；算距离淡出 `near`、凸边强度 `sEdge`、凹凸高度 `sH`；划痕让漆变浅，凸边掉漆露金属 |
| `#include <roughnessmap_fragment>` 后 | 粗糙度乘 B 通道起伏、G 通道拉丝；凸边更光滑（被磨亮）；划痕更粗糙 |
| `#include <normal_fragment_maps>` 后 | 导数凹凸：`dFdx(sH)`、`dFdy(sH)` 扰动法线（和 three 自带的 `perturbNormalArb` 同一个公式） |

**必须带上这两点，否则会出问题：**
- `customProgramCacheKey` 要把 kind 加进去（`'wear-' + mat.name + '-' + kind`），不然不同类别会共用一个着色器程序。
- 共享 uniform 用同一个对象引用（`sh.uniforms.uSurf = SURF.on`），这样开关只改一个值，所有材质一起变，不需要重新编译。

### 两个关键技巧

**距离淡出**（防止远处闪烁、摩尔纹）：
```glsl
float foot = length(fwidth(vWObj)) * 512.0 * uTile;      // 一个像素覆盖多少个细节图像素
float near = uSurf * (1.0 - smoothstep(1.5, 5.0, foot));  // 远了就不做凹凸
```

**屏幕空间凸边检测**（边缘磨损，不需要曲率贴图）：
```glsl
float curv = length(fwidth(vNormal)) / max(length(fwidth(vViewPosition)), 1e-5);   // ≈ 1/半径
float sEdge = smoothstep(4.0, 14.0, curv);
```
- 只有**平滑过渡的边**（圆角、倒角，法线是插值的）会被识别。平面和大圆柱为 0；硬折边（平面法线）也是 0，保持干净漆面。
- 机甲先做了分级 R 角，所以这一招效果很好。场景物体如果全是硬边，要先给需要磨损的边做小倒角，或者改用顶点色标记边缘。

## 6. 各类材质参数参考（MeshStandardMaterial）

| 材质 | 颜色 | 金属度 | 粗糙度 | 细节权重（kind） |
|---|---|---|---|---|
| 漆面钢板（机甲主甲） | 按涂装 | 0.3–0.5 | 0.4–0.5 | paint |
| 底漆、凹槽 | 比主色暗一档 | 0.35–0.45 | 0.55 | primer |
| 枪灰机加工件 | 0x50565c 左右 | 0.55–0.8 | 0.34–0.45 | metal |
| 镀铬活塞杆 | 0xaeb3b8 | 1.0 | 0.2–0.26 | chrome |
| 橡胶、软管、黑色接缝 | 0x0c–0x1d 灰 | 0.0–0.45 | 0.62–0.8 | rubber |
| **场景：混凝土** | 0x8a8a86 一带 | 0.0 | 0.85–0.95 | grain 1.5，rv 0.9，brush 0，edge 0.5（边角磨白） |
| **场景：结构钢（刷漆）** | 按警示色 / 灰 | 0.3 | 0.5 | paint，edge 1（边角露锈或金属） |
| **场景：防滑钢板、甲板** | 0x5a5f63 | 0.7 | 0.45 | metal + scratch 1 |
| **场景：沥青、码头地面** | 0x2a2c2e | 0.0 | 0.9 | grain 1.2，rv 1.0；积水处用粗糙度降到 0.1 表现 |
| **场景：玻璃** | 0x15171a | 0.6 | 0.1 | 不加细节，靠环境图反射；**不要用透射** |

经验：
- 金属度不要用 0.5 这种"半金属"去冒充漆面，漆是电介质（0–0.3）；本项目原有涂装为了观感用了 0.3–0.5，保留不动。
- 粗糙度起伏比颜色变化更出质感；颜色只做轻微变化。

## 7. 怎么测（改前、改后各测一次）

浏览器面板必须是显示状态，隐藏时不渲染（画布尺寸为 0）。

```js
// 纯渲染耗时：强制画 30 帧，用 readPixels 等 GPU 画完。比 rAF 帧时间准（rAF 会被 60 fps 封顶）
window.__gpu = (n = 30) => { const r = renderer, gl = r.getContext(); r.render(scene, cam); gl.finish();
  const t = performance.now(); for (let i = 0; i < n; i++) r.render(scene, cam);
  gl.readPixels(0, 0, 1, 1, gl.RGBA, gl.UNSIGNED_BYTE, new Uint8Array(4)); return (performance.now() - t) / n; };
// 平均亮度 + 过曝像素数：渲染后立刻把画布缩到 160×100 读出来
window.__luma = () => { renderer.render(scene, cam); const cv = document.createElement('canvas'); cv.width = 160; cv.height = 100;
  const x = cv.getContext('2d'); x.drawImage(renderer.domElement, 0, 0, 160, 100); const d = x.getImageData(0, 0, 160, 100).data;
  let s = 0, hi = 0; for (let i = 0; i < d.length; i += 4) { const l = 0.2126 * d[i] + 0.7152 * d[i + 1] + 0.0722 * d[i + 2]; s += l; if (l > 235) hi++; }
  return { mean: s / 16000, clipped: hi }; };
```

- 开关来回切几次，每种状态测两遍取最小值（第一次切换会编译着色器，偏慢）。
- 至少测两个机位：全景，和**近景（物体占满屏幕，最考验逐像素开销）**。
- 再用 rAF 测 180 帧，看中位数和 95% 分位，确认稳定在 16.7 ms 左右。
- 所有滑杆拉到最大和最小、所有按钮点一遍，看控制台有没有报错（着色器编译错误会在这里出现）。

## 8. 机甲上踩过的坑

- 第一版灯条太亮（主光条 3.4），圆角边出现一道道刺眼的白线，看着像多出来的线条。**调到 2.0–2.2，边缘提亮从 0.35 降到 0.25 才自然。** 场景里同理：先暗后亮，逐步加。
- 黑色接缝条、软管也走了做旧着色器，灰尘会把黑线刷成灰色。所以给做旧加了 `grime` 系数（橡胶 0.3，镀铬 0.5）。
- 浏览器面板隐藏时画布尺寸为 0，测亮度会报错，测帧时间也不准，先把面板显示出来。
- 改完 js 要先 `fetch(url, {cache: 'reload'})` 再刷新，不然浏览器用的还是缓存的旧模块。
