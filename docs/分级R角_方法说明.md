## 1. 上一版为什么失败（别再走这条路）

上一版是对**已经合并、已经布尔切割的网格**做后处理圆角，再离线烘焙成数据（27 MB）。结果：
- 圆角让表面**往外长**或位置变了，贴在面上的细节（4 个六角孔、编号、黑线）被吃掉、变成月牙，或者原来埋着的黑色接缝条露了出来。
- 网格是布尔汤（T 形接缝、非流形），通用倒角算法在这种网格上本来就不稳定。

**核心教训：不要在最终网格上倒圆。要在"每个零件还是简单凸体"的阶段做，而且只能往里削，不能往外长。**

---

## 2. 关键观察（先读代码得出的）

1. 腿、手、脚、关节件等，几乎全部由 `ConvexGeometry`（凸包）、`BoxGeometry`、`CylinderGeometry` 拼成，再用 `mergeGeometries` 合并，**合并时没有布尔运算**。
2. `paint.js` 已经把每个合并网格按连通性拆成"散件"（`components()`），每个散件就是一个原始凸体。
3. 胸甲、肩甲是"正视棱柱 ∩ 侧视棱柱 ∩ 俯视棱柱"，再减空腔、切缝（`torso.js`）。外形本身多数是凸的或接近凸的。

所以：**绝大多数零件在某个阶段都是凸体**，凸体可以做精确、稳定的圆角。

---

## 3. 核心算法：凸体圆角（`finallab/rounding.js` → `roundConvexPoints`）

数学上就是"先腐蚀再膨胀"（形态学开运算）：

1. 取凸体的所有面平面 `n·x ≤ d`（用 three 的 `ConvexHull`，共面三角形合并成一个面）。
2. 每个面向内平移 R：`n·x ≤ d − R`，得到"内缩凸体"。
   - 求内缩凸体的顶点用**对偶法**：找一个内点 c，把每个平面变成对偶点 `n / (d − R − n·c)`，对这些点求凸包，凸包的每个面对应内缩凸体的一个顶点 `v = c + m / k`（m、k 是对偶面的法线和常数）。这样只需要两次凸包，不用三重循环求交，退化的小面会自动消失。
3. 对内缩凸体的每个顶点 v，找出经过它的平面法线集合 N（法向锥），在半径 R 的球面上铺点：
   - 每个面法线 n：点 `v + R·n`（这些点正好落在**原来的平面上**）；
   - 每两条法线之间按角度插值（slerp），每段不超过 `step`（大甲 22.5°，小件 45°，螺栓 90°=单段）；
   - 三面以上的角再加一个平均方向点。
4. 对所有这些点再求一次凸包，就是圆角后的零件。
5. **法线直接给解析值**：每个点的法线就是它的球面方向 d。平面上法线 = 面法线，圆弧上光顺过渡，平面和圆弧之间切线连续。

得到的性质（这正是用户要的）：
- 每个平面仍在原位置，只是四周让出 R 宽的圆弧 → **轮廓、贴合面、配合面不变**，贴在面中间的细节不会被吃掉。
- 所有点都在原凸体之内 → **体积只减不增，不会变胖，不会顶进别的零件**。
- 宽度小于 2R 的小倒角面会被圆弧吸收，这和真实加工一致。
- R 上限 = 零件最薄处 × 0.3，薄件自动用更小的 R。

## 4. 接入流程（现在在 `finallab/model.js` 的 `buildFinishedModel`）

> 2026-10-23 起，另一个模型把装配流程从 lab.js 挪进了公共文件 `finallab/model.js`，成品间和穹顶机场都用它。改流程时改 model.js，用局部插入，别整文件重写。

顺序很重要：

```
建模 → paint（拆散件、分材质）→ applyTweaks
  → 【smoothShading(HEAD)：头部曲面去竖纹，见第 11 节】
  → 【roundParts：逐散件倒圆】
  → 【transferNormals：给肩甲/胸甲还光顺法线】
  → reliefShoulders / reliefAll（切下沉面板）
  → 【snapSeams：悬空黑线贴回表面，见第 10 节；必须在倒圆和切面板之后】
  → details → 贴花/灯（射线贴面）→ 关节光环 → 推进器
```

- 倒圆放在**切面板、贴花、装灯之前**：后面这些步骤都用射线贴到实际表面，所以会自动贴合新的表面。
- `roundParts(root, pickRadius)`：对每个网格的每个散件做凸性检查（所有顶点和三角形中心都在凸包表面上），凸的就按规则选 R、就地替换；非凸的原样保留。网格、层级、轴心、材质分组都不变，**绘制数不变**。
- 计算在世界坐标做，再变回局部坐标。**坑：左臂的组是镜像的（scale x = −1），变回局部后三角形绕序会反，要检查 `matrixWorld.determinant() < 0` 并交换每个三角形的第 2、3 个点**，否则会看到零件内表面，射线也打不中。
- 原几何存到 `mesh.userData.roundedFrom`。`jointLights.js` 靠识别"完美圆柱"来找轴、装光环，倒圆后识别不出来，所以改成读 `roundedFrom`（端面位置没变，光环位置照旧）。
- 头和颈部已认可、不动：`NR.group` 的 `noRelief` 标记必须在倒圆**之前**设置（原来是在之后设的）。

## 5. 布尔外壳（胸甲、肩甲）：在布尔之前倒圆（`torsolab/torso.js` → `roundBody`）

- 外形 = 三视图棱柱相交体。**先对这个外形倒圆，再减空腔、切缝**：切口、凹槽、导弹舱的口子自然保持硬边（符合"装配接口/切口保留"）。
- 外形不是凸的（弯折板、领口 V 形缺口）：对它的**凸包**倒圆，再和"原形各轮廓向外扩 0.008"求交。凹的折线保持硬边；外扩 0.008 是为了避免共面布尔出错。
- 这些网格之后还会被 arm.js 切成滑板，并用 `computeVertexNormals` 重算成平面法线。所以倒圆时登记一份世界坐标的参考面（`ROUND.refs`），全部切完以后由 `transferNormals` 把参考面上的光顺法线插值还给落在参考面上的三角形；切出来的面不在参考面上，保持平面法线。
- 肩甲装配时会在 y 方向压缩 0.94 再下移，参考面要做同样的变换（`transformRefs`），法线按逆转置变换。

## 6. 分级规则（`finallab/roundRules.js`，单位：1 = 2.05 m）

| 类别 | R | 圆弧分段 |
|---|---|---|
| 胸甲、肩甲外壳 | 0.09 | 22.5° |
| 腿正面主甲（横边、竖向长棱都处理） | 0.07 | 22.5° |
| 腿内外侧板、后侧片、小腿肚片（2026-10-23 用户要求加上） | 0.045 | 30° |
| 其他大型主甲（最长边 ≥ 2.5，厚 > 0.25） | 0.065 | 22.5° |
| 肩顶翼板 | 0.06 | 22.5° |
| 中型护甲、手、脚 | 0.035 | 30–45° |
| 小护甲 | 0.018 | 45° |
| 关节件、机架 | 0.022 | 单段 + 圆柱侧面法线合并 |
| 螺栓、轴端、小凸耳 | 0.008–0.01 | 单段 |

**保留硬边：** 刀刃段 `LF.seg*`、锯爪 `LR.claw*`、任意内角 < 40° 的尖件、反应堆风扇叶、灯、黑色接缝条、排气口喉道、镀铬活塞杆和销轴（滑动/配合面）、头颈。
（第一版按交接提示词把腿两侧独立护甲留成硬边，用户看了以后要求也加 R，已改。**提示词里"保留硬边"的清单不一定是用户本意，做完要让用户看。**）

圆柱法线合并（`merge: 12°`）只用于关节件：32 边的圆盘相邻侧面合成一个方向，否则三角面会翻倍。**装甲不能开合并**，否则刻意做的浅折面（10° 左右）会被抹成渐变。

## 7. 验证方法（数值，不靠截图）

- **细节检查** `__roundCheck()`：任何别的零件（黑线、螺栓、灯、贴花、进气罩）的顶点，如果落在"原凸体之内、圆角体之外"的那一薄层里，就说明它原来贴在或埋在棱边上，现在会露出来或悬空。按网格汇总。当前结果只有护甲之间互相嵌着的位置（露出 < 1 cm）、右肩铰链节（约 5 cm），没有黑线、灯、贴花。
- **和原版逐项对比**（`?round=0` 和 `?round=1` 各载入一次）：可见网格名单、贴花/灯落点日志、下沉面板数量。关节光环丢失就是这样发现的（原因是镜像绕序和 `roundedFrom`）。
- **功能**：53 个滑杆拉到最大和最小、41 个按钮、全部下拉都跑过，没有报错。
- **性能**：三角面 39 万 → 55 万，每帧 18.6 → 19.4 ms，绘制数不变，载入慢约 2 秒。不逐帧计算。

## 10. 悬空黑线：贴回护甲表面（`finallab/seams.js` → `snapSeams`）

**现象：** 用户截图里大腿外侧一条黑线浮在护甲外面。

**原因：** 黑色接缝条、刻线是 `obox` 小方条，按坐标手放。后来护甲改形状、倒 R 角、切下沉面板，表面挪开了，线就留在空中。查出来的有：大腿外侧接缝离面 0.18、大腿内侧板前缘线 0.77、胯部中缝 0.09、脚趾缝两端 0.18，还有小腿、脚、前臂、手掌、肩滑板上几条两端翘起来的。

**做法：**
1. 只处理 dark 材质、12 个三角面的方条（obox），长 ≥ 0.3、薄 ≤ 0.15。软管、布尔切出来的接缝不碰。
2. **判断要不要动：** 方条的角点或中心，只要有一个在实体外、而且离背后的表面超过半个厚度，就算"有一部分露在空气里"。完全埋在护甲里的不动——**否则会多出原版没有的黑线**（用户之前明确反感过）。
3. **重建成贴面带子：** 沿长度方向每 0.1 取一个截面，截面两个角分别从外面 1.2 处向内打射线，取同一零件最外层的护甲表面，带子中心面贴在表面上（一半埋入，一半凸出）。这样能跟着折面和 R 角走；8 个顶点的直方条做不到。
4. 只投到**同一个父级（同一刚体零件）**里的实体网格上，不会贴到旁边的手臂上；带子留在原网格、原父级里，随零件一起动。
5. 调用位置必须在 `roundParts` 和 `reliefAll` **之后**（这两步都会改表面），在贴花和灯之前。头颈跳过（`noRelief`），那里的"离面细条"是驾驶舱内部件，不是刻线。

**踩过的坑（都在代码里处理了）：**
- **外侧判断：** 一开始用"沿薄方向哪边离表面远，哪边就是外"。大腿外侧那条线旁边 1 cm 有六角侧板的凸边，于是被判反，投到腿里面去了。改成**数两个方向各穿过几个表面，少的那边是外侧**。
- **方截面细条：** 脚趾缝是 0.03 × 0.03 的方截面，两个薄向打平，挑中了水平方向，结果从侧面投、越过了脚趾。改成**打平时取离护甲更近的那个方向**。
- **接缝漏射：** 大腿那条线的下角正好落在上下两层护甲的分界线 y = −17.5 上，射线从缝里穿过去，什么都没打中。改成**打空时把采样点往带子中心挪 0.01 / 0.03 / 0.06 / 0.1 再试**。
- **真实厚度：** 方条略有倾斜时，包围盒厚度（0.097）比真实厚度（0.03）大三倍，带子会变成凸起的黑板。改成**用方条最短的边长当厚度**。

**验证：** 对每条细线采样点，不在实体内的就沿 6 个轴向找最近表面，取最大距离。修完以后所有目标线 ≤ 0.015（比线本身还薄）。注意：这个检查要按网格分开跑，只用同父级的实体当探测面；一次对全身所有点、所有网格跑会超时。

## 11. 曲面竖纹：平滑组法线（`finallab/surface.js` → `smoothShading`）

**现象：** 头盔上一条条竖纹（材质不变，只是明暗一条一条的）。

**原因：** 头盔、脸颊、传感框这些曲面壳，是用很多窄条平面拼的，每条都按平面法线打光，相邻条之间亮度跳变。量了一下，相邻面夹角大多是 2–8°，而刻意的折线都 ≥ 25°，中间几乎没有，所以 20° 是个干净的分界。

**做法：** 只改法线，不动几何、材质、面数。
1. 共享一个顶点位置、而且夹角 < 20° 的面，并成同一个**平滑组**（并查集）。
2. 每个角点的法线 = 同组、同位置、与自己夹角 < 60° 的面的法线按面积加权平均。
3. 夹角 ≥ 20° 的折线分属不同组，保持硬边。

**坑：** three 自带的 `toCreasedNormals` 不够用。它只拿"与自己夹角 < 阈值"的邻面平均，窄条一路慢慢弯的时候，相邻两个面挑到的邻面集合不一样，法线还是对不上，条纹只少了大约三分之二。换成平滑组以后，头盔条纹接缝从约 3800 处降到 29 处。

**验证：** 统计同一位置上几个顶点法线之间的夹角分布：0.5–20° 的数量就是可见条纹接缝，≥ 20° 的是保留的硬折线。

## 12. 这一轮的通用教训

- **交接提示词可能来自做错的那个 AI**，里面的要求要自己判断（比如"腿两侧保持硬边"，用户其实想要 R 角）。用户真正的诉求：该硬的地方硬，其他地方做点过渡，不要像铁盒子；**不能吃掉细节，也不能多出原版没有的线**。
- 修"悬空"类问题时，先**数值找全**（全身扫一遍），不要只修截图里那一条。
- 另一个模型同时在改项目：动公共文件（`model.js` 等）前先读最新版本，用局部插入；`assert` 定位不到时先 diff 看清楚别人改了什么，不要硬改。
